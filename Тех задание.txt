Техническое задание: FlowFocus — система управления задачами с интеллектуальным планированием
Версия: 8.4
Дата: 16.11.2025 10:00
1. Введение
1.1. Назначение системы
FlowFocus — веб-приложение для управления персональными задачами с интеллектуальным планированием, поддержкой зависимостей между задачами, балансировкой нагрузки и визуализацией прогресса.
1.2. Отличительные особенности
Автоматическое распределение задач с учетом времени, сложности и блокеров
Гибкая система приоритетов
Поддержка сложных условий выполнения через систему зависимостей
Балансировка "интересных" и "сложных" задач
2. Функциональные требования
2.1. Управление задачами
2.1.1. Создание и редактирование задач
Быстрое добавление через фиксированный компонент внизу экрана (часть Main Layout)
Два режима создания:
Быстрая отправка → попадает в "ненастроенные"
Расширенное создание → полная форма с настройками попадает сразу в алгоритм распределения дел
Основные поля:
Название, приоритет, дата выполнения, теги
Дополнительные поля:
Связи с другими задачами (автодополнение)
Описание задачи
Тип отображения: Вложенное/Самостоятельное
Сложность (1-100)
Интересность (1-10)
Время выполнения (в часах)
Флаг избранного
2.1.2. Система приоритетов
Варьируется 0-100, для референса есть значения, зафиксированные на значениях Фибоначчи (тех значения int, enum для чистой логики кода и ui-референсов)
Референсы задач по приоритетам:
0: Гарантированные (автовыполнение)
1: Неотложные (удаляются если не выполнены сегодня)
3: Срочные (социальные обещания)
5: Важные (бытовые дела)
8: Среднесрочные (несколько дней)
13: Долгосрочные (недели/месяцы)
21: Саморазвитие
34: Мечты
Приоритет по умолчанию: Для задач, добавленных без даты и без приоритета, устанавливается значение 18.
2.1.3. Система статусов
НеНастроена, Запланирована, Завершена, Неактуальна
Автоматическая маркировка неактуальными при определенных условиях
Логика установки статусов:
НеНастроена — устанавливается только для задач, добавленных через интерфейс быстрого добавления без настройки.
Завершена — устанавливается при нажатии на чекбокс в карточке задачи или при выборе завершения через специальные интерфейсы (например, при начале нового дня).
Неактуальна — устанавливается при активации соответствующего чекбокса в интерфейсе настройки задачи или через соответствующую кнопку при менеджменте старыми задачами.
Запланирована — устанавливается для всех остальных задач.
Напрямую через выбор в настройках карточки статус не настраивается.
2.2. Система зависимостей между задачами
2.2.1. Типы связей
Блокирующие — задача не может быть начата пока блокер не завершен
Связанная — смысловая связь без блокировки
2.2.2. Правила валидации
Запрет ссылок на себя
Автоматическое двустороннее отражение связей
В UI циклическая зависимость предполагается, но технически она не должна вызывать проблем
2.2.3. Логика выполнения для блокеров
Настройка условий AND/OR между блокерами
Визуальная группировка в "скобки" для сложных условий
Автоматическое завершение родительской задачи при выполнении условий
2.3. Алгоритмическое планирование
2.3.1. Архитектура планировщика
Интерфейс для различных стратегий планирования
Базовая реализация с перепланированием просроченных задач
Расчет приоритетов на основе формулы
2.3.2. Факторы распределения
Дедлайны и даты выполнения
Дневные лимиты времени и сложности
Баланс интересности задач
Зависимости и блокеры
2.3.3. Управление пересчетом
Ручной пересчет с различными опциями
Автоматический пересчет при добавлении задач (опционально)
2.4. Управление прокрастинацией
Балансировка "приятных" и "сложных" задач
Предотвращение перекоса в нагрузке
Учет психологических факторов
2.5. Повторяющиеся задачи
Поддержка различных типов повторений
Только одно активное повторение в списках
Каскадное копирование дочерних задач
Автоматическое создание следующего повторения
Интерфейс настройки повтора:
При выборе типа "Повторяющаяся" появляется выбор алгоритма повторения.
Типы алгоритмов и элементы управления:
Периодический (каждые N дней/недель): Поле для ввода числа и выпадающий список для выбора единицы измерения (дни/недели).
По числам месяца: Календарь, позволяющий выбрать конкретные числа месяца. Реализация: поэтапный выбор — нажатие на календарь выбирает дату или период, последующие нажатия дополняют новыми датами или периодами.
По дням недели: Отображается семь кнопок (Пн, Вт, Ср, Чт, Пт, Сб, Вс) для выбора дней.
2.6. Визуализация данных
2.6.1. Цветовая кодировка
Градиентная цветовая полоска приоритетов — вертикальная, располагается в левой части карточки задачи.
Визуальные стили для разных статусов:
Всего три стиля карточки: Дефолтный, Завершена и Неактуальна.
Предупреждающие индикаторы
2.6.2. Отображение зависимостей
Многоуровневый вложенный список связей
Группировка по типам связей
Поддержка любой глубины вложенности
3. Пользовательский интерфейс
3.1. Структура интерфейса
3.1.1. Основные разделы
Главная — задачи на сегодня (без кнопки "Настройки" в списке дел)
Завтра — задачи следующего дня
Все задачи — полный список с фильтрацией
Ненастроенные — задачи, требующие подтверждения
Настройки — параметры приложения
3.1.2. Фильтрация и сортировка
Фильтры по статусу, тегам, приоритету, дате
Сортировка по дедлайну, приоритету, интересу, сложности
Переключатель показа завершенных задач
3.1.3. Режимы отображения
Список — линейное представление
Сетка — карточное представление
3.2. Компоненты интерфейса
Контейнер отображения задач с фильтрами
Карточка задачи с полной информацией
Модальные окна редактирования и подтверждения
Компонент быстрого добавления
Визуализатор зависимостей
Кнопки: На всех кнопках приложения должен быть отображен выровненный по центру текст. Иконка + текст не должны быть сдвинуты.
Карточка задачи:
Вертикальная цветная полоса-индикатор приоритета слева.
Присутствует чекбокс для завершения/отмены завершения задачи.
Дедлайн визуально выделен.
3.3. Обработка системных событий
3.3.1. Начало дня
Подтверждение автовыполнения гарантированных задач
Обработка невыполненных неотложных задач
Перенос невыполненных задач
3.3.2. Система предупреждений
Детектирование нехватки времени
Предупреждения о скором завершении дня
Уведомления о заблокированных задачах
3.4. Диалоговые окна и панели
3.4.1. Перечисление простых диалоговых окон:
Диалоговое окно "Панель статистики" - по кнопке на страницах с отображением дел
Параметры отображения задач
Диалоговое окно подтверждения удаления
Диалоговое окно редактирования задачи
3.4.2. Настройки задачи: Диалоговое окно для настройки новой задачи, вызываемое по нажатию на иконку-шестеренку рядом с кнопкой "Добавить" (представляющую собой галочку без текста) в компоненте быстрого добавления.
В настройках задачи помимо plain полей должна быть раскрывающаяся часть "Расширенные настройки"
Даты, в которые приоритет авто-повысится до 1, 3, 5 (если приоритет дела менее важный)
Плюс настройка связей с другими задачами по авто-дополнению, тип этих связей и стиль отображение при связи = блокер
4. Технические требования
4.1. Архитектура системы
Frontend: Blazor Server с MudBlazor компонентами
Backend: .NET 10
База данных: SQLite с Entity Framework Core
Паттерны: SOLID, Repository Pattern с кэшированием
4.2. Модели данных
4.2.1. Сущность "Задача"
Идентификатор, название, описание
Теги, статус, приоритеты (пользовательский и вычисленный)
Метрики: интересность, сложность, время выполнения
Даты: дедлайн, планирования, создания
Флаги: избранное, повторение
Коллекция зависимостей
4.2.2. Сущность "Зависимость"
Идентификаторы связанных задач
Тип связи (enum: блокирующая, вложенная, etc.)
Логика выполнения (AND/OR)
Дополнительные параметры условий
4.2.3. Сущность "Настройки пользователя"
Время начала дня
Дневные лимиты времени и сложности
Флаги автоматических операций
Маппинг дат для повышения приоритета (для приоритетов 1, 3, 5) в виде грида 3x2 соотв. и только в случае если приоритет задачи ниже

4.3.1. Определение временных периодов
Настраиваемое время начала дня
Корректное отнесение задач к дням
4.3.2. Валидация зависимостей
Обнаружение и предотвращение циклов
Проверка корректности связей

Кэширование на уровне репозиториев
Инвалидация при изменении данных
4.4. Хранение данных
SQLite с автоматической миграцией
Автоматическое создание БД при первом запуске

4.5. Структура решения
Проект-библиотека FlowFocus.Core для всей бизнес-логики, интерфейсов и всего, что не требует библиотек и фреймворков.
Папка Models - для основных понятий приложения
Проект-библиотека FlowFocus.Data - для работы с данными, EF
Запускаемое Blazor Server приложение FlowFocus.WebApp - для визуальной части приложения и всего причетающегося. Структура стандартная, сгенерированная MudBlazor template'ом. Плюс папки:
Pages для .razor с @page ""
Dialogs для диалоговых окон
Components для .razor, используемых на страницах
